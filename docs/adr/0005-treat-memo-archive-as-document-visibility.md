# ADR 0005: メモのアーカイブも可視性属性として扱う

- Status: Accepted
- Date: 2026-09-24
- Deciders: Repository owner
- Amends: [ADR 0004](0004-treat-archive-as-document-visibility.md)

## Context

ADR 0004はプロジェクト、案件、タスクの`isActive`を可視性属性とし、アーカイブ済みでも通常文書と同じように編集できるようにした。一方、Non-goalsで「メモのアーカイブと復元の挙動を変更しない」としたため、メモだけがアーカイブ済みを編集禁止として扱い続けていた。

- サーバーはアーカイブ済みメモへの本文保存を`missing`、復元以外のmetadata更新を`rejected`として拒否していた。
- 初期化データの`getMemos`はアクティブなメモだけを返し、アーカイブ済みメモはメモリ上の文書ストアに存在しなかった。クライアントは検索結果の情報から表示用の仮エンティティを作り、読み取り専用で表示していた。
- アーカイブ済みメモを後から復元するUIがなかった。

この結果、ADR 0004がタスク文書で解消した問題がメモには残っていた。別タブで選択中のメモをアーカイブすると、そのタブの未送信本文は保存不能になる。また、同じ「アーカイブ」でも文書の種類によって編集可否と復元経路が異なり、利用者から見て一貫しない。

## Decision

メモの`isActive`も、プロジェクト、案件、タスクと同じく通常ナビゲーション上の可視性を表すmetadataとして扱う。

- サーバーは、実在する非activeなメモへの本文・metadata更新を拒否しない。`missing`は行が存在しない場合だけを表す。
- 初期化と再読み込みのメモ一覧はアーカイブ済みメモも含めて返す。クライアントは文書ストアに全メモを保持し、サイドバーではactiveなメモだけを表示する。
- アーカイブ済みメモは検索から開き、通常のメモと同じく本文、名前、タグを編集できる。EditorStateを読み取り専用にしない。
- 選択中の文書がアーカイブ済みの場合、メタ欄に「アーカイブ済み」と「アーカイブを解除」を表示する。この表示と復元操作はメモ、プロジェクト、案件、タスクで共通とする。親のアーカイブによって非表示になっているだけの文書では、解除ボタンを出さない。

ADR 0004のNon-goalsのうち「メモのアーカイブと復元の挙動を変更しない」は、本ADRで置き換える。その他の決定はADR 0004のまま維持する。

## Non-goals

- メモのアーカイブ一覧を追加しない。アーカイブ済みメモは検索から開く。
- 文書を物理削除する仕組みを追加しない。

## Consequences

### Positive

- 別タブでアーカイブされたメモでも、未送信本文を通常のCASで保存できる。
- アーカイブの意味、編集可否、復元操作が文書の種類によらず一致する。
- 検索結果から仮エンティティを組み立てる読み取り専用の経路を削除できる。

### Negative

- アーカイブ済みメモの本文も初期化データに含まれ、メモリ使用量と初期化の転送量が増える。
- アーカイブを改変禁止と見なすことはできない（ADR 0004と同じ）。

## Implementation

- 文書CAS: `src/DocumentSyncService.ts`
- メモ一覧の取得: `src/MemoService.ts`
- メモのEditorStateとアーカイブ表示: `client/components/memo/MemoTab.tsx`
- アーカイブ表示と解除操作: `client/components/shared/ArchivedBadge.tsx`
- タスク文書のアーカイブ表示: `client/components/task/TaskContent.tsx`

## Verification

- アーカイブ済みメモの本文とmetadataをrevision CASで更新できる。
- アーカイブ済みメモをサイドバーに表示せず、検索から開いて編集できる。
- メタ欄の「アーカイブを解除」でメモ、プロジェクト、案件、タスクを復元できる。
